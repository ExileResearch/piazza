## Database and readiness

Ten EntitySchemas implement B01–B03/D02–D08; D01 supplies shared columns without a table. Use millisecond UTC timestamps, UUIDv4 IDs, positive mutable versions, bounded JSON/arrays and finite states. Canonical enums feed constraints. Secret hashes/encrypted factors are excluded from normal ORM selections. These are persistence rows, not wire DTOs; application validation and explicit projection remain required. SQL constraints do not reproduce every Zod refinement.

Composite foreign keys bind instances to their controller and configuration's agent, credentials to the instance's controller, grants to the controlling human and optional instance's agent, and approvals to the controlling human. The instance's extra controller ID is a database-only consistency column. These constraints prevent mismatched ownership records; they do not replace scoped reads or permission enforcement in later APIs. Future artifact foreign keys await their actual tables.

The generated reversible baseline migration uses a transaction and indexes controller/agent/instance, expiry, session families, configuration sequence and approval lookup fields. Synchronization, automatic extension installation, SQL logging and destructive schema dropping are disabled. Migrations run explicitly unless automatic application is deliberately enabled. With `DB_MIGRATIONS_RUN=true`, initial connection or recovery can apply migrations; leave it false for migration-read-only dependency probes. Native `gen_random_uuid()` works on PostgreSQL 17; generated UUID metadata and native array defaults avoid perpetual migration drift. Generated TypeORM imports need `import type` under verbatim module syntax. Runtime and CLI share datasource metadata/options without reading `.env` merely by importing application factories.

Readiness uses a read-only query of the existing migration tracking table to check connectivity and pending migrations (missing table means unavailable), plus an Appwrite bucket metadata request with a timeout and redirects disabled. Missing configuration or any failure returns a minimal 503. An unavailable database leaves liveness available and retries connection on subsequent readiness requests. This is not an upload/scan/release adapter or provider acceptance test. Real Appwrite writes, Brevo delivery, backup/restore, retention and multi-process behavior remain later gates.

## Verification

The verification helper runs typecheck/build/lint, unit tests, HTTP E2E and PostgreSQL integration. Its database helper owns a uniquely named, localhost-only temporary-storage PostgreSQL 17 container and removes it afterward; it does not use Compose or the operator's database. An explicit external `TEST_DATABASE_URL` is restricted to localhost/test-prefixed databases and needs CREATEDB: each run creates/removes a separate random database.

Recorded evidence: compiled-server smoke testing returns liveness 200 and readiness 503 during an actual database connection failure, without secret diagnostics. `npm run verify` passes typecheck/build/lint, 40 unit tests, 11 HTTP E2E tests and 6 PostgreSQL integration tests on Node 24.21.0 and PostgreSQL 17.11. Unit tests exercise configuration, redaction, actor classification and storage failures. HTTP tests use the real Nest boundary with test-only controllers and substituted dependencies; they verify strict input/output, errors, correlation IDs, CORS/CSP, rate bounds, probes and development docs. Database tests apply/revert/reapply the migration, check no metadata drift, transaction rollback, unique/check constraints, default secret exclusion, cross-controller consistency, pending/missing migrations without probe DDL and unavailable connections. They do not claim working human auth or deployed cross-operator API journeys.

Node emits the expected experimental VM modules warning during Jest. TypeORM's PostgreSQL schema inspection also emits pg's deprecation warning for overlapping queries on a client; pg is pinned to 8.x. No application query loop relies on that pattern; inspect upstream compatibility before moving to pg 9. This warning does not skip any migration or constraint check.
