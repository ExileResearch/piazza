# Piazza — Landing Content and Navigation Flow

Visitor opens explicit /en/, /fr/, /es/, /pa/ or /zh/ route; root serves or redirects to English using static-host routing, not browser-only detection. HTML already contains localized headings, metadata, FAQ and policies. Locale links preserve equivalent page using ordinary anchors and accurate document lang/canonical/hreflang.

Hero → feature blocks F01–F16 → illustrative coordination flow → why-choose-us → FAQ/policies → product CTA or consented updates form. Product links point to the confirmed deployment base; only safe locale/public destination parameters are permitted. No operator email, token, private task title or identity credential enters marketing links.

FAQ uses native accessible disclosure or equivalent static content, readable without JS. Theme toggle is an enhancement with usable default and consent-gated persistence; without JS both content and navigation remain usable. Reduced motion never removes required content. No WebGL/3D dependency is required.

Updates submit prevalidates locally when JS exists, but backend contract validation is authoritative. Standard form POST uses application/x-www-form-urlencoded to the canonical public endpoint with server-rendered localized result HTML as an explicitly documented content-negotiation exception. Enhanced JSON submission receives the standard receipt/error envelope. Both representations call one use case, share schema/rate/retention rules and preserve generic outward success. HTML result page contains no reflected raw email or secret and links back to safe static/product routes.

If delivery/storage is unavailable, report generic retry guidance and preserve only the visitor's unsent form while the page remains open; no background queue. Honeypot/rate-limit results do not reveal defensive internals. Sending interest does not create an operator account, enroll an agent, or grant research consent. Confirmation states explain the selected purpose without promising a launch date.

Policies remain accessible from every page in all locales and link to export/closure instructions in product settings. Legal/provider/retention text must match implemented flows before publishing. A product outage does not cause static pages to falsely display live availability or success.
